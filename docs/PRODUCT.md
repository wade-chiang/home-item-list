## 1. 產品定位

**家庭耗材更換提醒器** — 解決「該換了但沒人記得」。

核心不是清單管理，是「**到期推算 → 提醒 → 換好了 → 重新推算**」的循環。使用者只做兩件事：設定週期、按「換好了」。

第二層價值（P4）：因為每次採購都有記錄，可以回答「今年在家用耗材上花了多少」「哪一項最燒錢」。

## 2. 資料模型（PocketBase collections）

### 欄位型別通則

**日期欄位用 `text`**，存 `YYYY-MM-DD` 純日期字串，並以 `pattern` 檢查格式。P1-6 實測後定案，理由見 CLAUDE.md「日期只存日期」。領域層看到的都是 `YYYY-MM-DD` 字串。

**`photos` 與 `purchases` 的欄位已在 P1-5 建立，但領域型別（`src/shared/types.ts`）與 repo 層到 P2 才納入**：照片見 P2-3、採購見 P2-6。

### `locations` 位置

| 欄位 | PB 型別 | 說明 |
|---|---|---|
| `householdId` | text | 保留欄位，目前固定單一值 |
| `name` | text (required) | 例如「主臥」 |
| `icon` | text (required) | Lucide icon 名稱，從精選清單挑選 |
| `sortOrder` | number | 首頁位置區塊的順序 |

### `categories` 類別

物品的分類，**只負責分組與 icon**，不帶預設週期、預設提醒天數、預設單價。

*為什麼不帶預設值*：同類別的耗材週期並不相同 —— 餐廳冷氣少開可以很久才換，主臥冷氣天天開週期就短；同樣是水龍頭濾心，不同品牌的過濾量也不同。週期取決於使用頻率與型號，不取決於類別。

| 欄位 | PB 型別 | 說明 |
|---|---|---|
| `householdId` | text | 保留欄位 |
| `name` | text (required) | 例如「冷氣濾網」 |
| `icon` | text (required) | Lucide icon 名稱，從精選清單挑選。物品沿用類別的 icon |
| `sortOrder` | number | |

### `items` 物品

| 欄位 | PB 型別 | 說明 |
|---|---|---|
| `householdId` | text | 保留欄位 |
| `location` | relation → locations (required) | |
| `category` | relation → categories (required) | |
| `label` | text | 補充名稱，選填。同位置、同類別有兩個以上時用來區分 |
| `leadDays` | number（最小 0） | 提前提醒天數。新增時帶入 `settings.defaultLeadDays`。0 表示到期當天才提醒；必須有值由 repo 層把關，見 CLAUDE.md「型別要自己顧」 |
| `note` | text | 安裝位置、機身型號等注意事項 |
| `paused` | bool | |
| `pausedUntil` | text | `YYYY-MM-DD`。暫停時**必填**，到期自動恢復 |
| `photos` | file（Max Files 5） | 機身、型號貼紙、濾網裝在哪 |

**顯示名稱** ＝ 位置 ＋ 類別 ＋ 補充名稱（有填才顯示），例如「主臥 · 冷氣濾網」「廚房 · 濾心 · 水槽」。推導值，不存欄位。

物品**沒有**品牌、型號、週期欄位 —— 「目前型號」「目前週期」取自最近一筆更換紀錄（§3.3）。

### `logs` 更換紀錄

| 欄位 | PB 型別 | 說明 |
|---|---|---|
| `item` | relation → items (required) | |
| `replacedOn` | text | `YYYY-MM-DD`。**可空**：選了「不知道上次更換日」時留空 |
| `expectedDue` | text | `YYYY-MM-DD`。只在 `replacedOn` 為空時使用；補上日期時清掉 |
| `cycleDays` | number (required) | 這次裝進去的耗材多久該換 |
| `brand` | text | 選填 |
| `model` | text | 選填 |
| `photos` | file（Max Files 2） | 耗材包裝、型號標籤。「拍照自動填入品牌型號」用的是這裡的照片 |
| `note` | text | 這次更換的備註，例如購買通路、這次的狀況。選填 |
| `purchase` | relation → purchases（可空） | 這次有買新的才有。**空 = 用既有存貨** |

**每個物品至少一筆更換紀錄**：新增物品時就建立第一筆；只剩一筆時不能刪除。

### `purchases` 採購紀錄

跟更換紀錄分開的理由：**一捲 400 元的濾網可以換四五台冷氣**。記在更換紀錄上會逼使用者第一台記 400、後四台記 0，單次成本是假的。分開之後「今年在冷氣濾網上花了 1,200 元」永遠正確，跟換了幾次無關。

| 欄位 | PB 型別 | 說明 |
|---|---|---|
| `householdId` | text | 保留欄位 |
| `unitPrice` | number（最小 0） | 元，整數。0 表示贈品 |
| `quantity` | number (required) | |
| `unit` | text | 「捲」「片」「個」 |
| `note` | text | |

採購紀錄**不存名稱、類別與日期**，都由建立它的那筆更換紀錄推導：顯示為 `類別 · 品牌型號`，沒填品牌型號時只顯示類別；採購日期就是那筆更換紀錄的日期。

總額 = `unitPrice × quantity`，**推導值不存欄位**。

刪除更換紀錄或物品時，沒有其他更換紀錄指向的採購紀錄一起刪除；復原時一起還原。

> 庫存（`quantity` 減掉關聯的更換紀錄數 = 還剩幾捲）**目前不做**，但這個結構讓它之後可以無痛加上。

### `settings` 全域設定

key-value 兩個 text 欄位。目前只有 `defaultLeadDays`（新物品預設提前提醒天數，預設 7）。P1-5 的 migration 會建立 `defaultLeadDays = 7` 這一筆。

## 3. 到期與狀態計算

唯一實作在 `src/shared/due.ts`。

### 3.1 到期日

```
due = 最近一筆更換紀錄的 replacedOn + 該筆的 cycleDays
若最近一筆的 replacedOn 為空 → due = 該筆的 expectedDue
```

**「最近一筆」**：依 `replacedOn` 由新到舊；`replacedOn` 為空的排最後；同一天有多筆時，較晚建立的為較新。

### 3.2 狀態

判斷順序（**由上而下，先中先算**）：

| 狀態 | 條件 | 視覺 |
|---|---|---|
| `paused` | `item.paused === true` 且今天早於 `pausedUntil` | 灰，不出現在首頁的位置區塊，改由「N 項已暫停」常駐顯示 |
| `overdue` | `due < 今天` | 磚紅 |
| `soon` | `due - 今天 <= item.leadDays` | 赭黃 |
| `ok` | 其他 | 中性色 |

**排序在前端做。** due 是推導值，PocketBase 不知道它，所以不能用 API 的 `sort` 參數。物品是幾十筆等級，全部撈回來在前端排序完全沒問題。

### 3.3 目前型號與目前週期

- **目前型號** ＝ 最近一筆更換紀錄的品牌 ＋ 型號
- **目前週期** ＝ 最近一筆更換紀錄的週期

都是推導值。品牌型號沒填時，畫面上**留空，不顯示替代文字**。

### 3.4 型號變更與週期變更標示

更換歷史的每一筆，跟前一筆（較舊的那筆）比較：

- 品牌或型號不同（兩者各自整理後比較）→ 標示「型號變更」，包含從有品牌換成沒填。比較前先整理字串（見 CLAUDE.md「品牌型號的比較只能有一份字串整理」）
- 週期不同 → 標示「週期 90 → 60」

顯示時才計算，不存欄位。補填或修改品牌型號後，標示自動重算。

### 3.5 實際間隔回饋（只提示，不自動改）

物品詳情頁計算有日期的更換紀錄之間的實際間隔。**至少有兩個間隔、而且平均與目前週期差 10 天以上**才顯示：

```
目前週期 90 天，實際平均 118 天換一次（近 3 次間隔：112 / 130 / 112 天）
[ 把目前週期改成 120 天 ]
```

- 平均只取最近 3 次間隔，不足 3 次時有幾次算幾次
- 建議值：平均 30 天以上四捨五入到 10 天；30 天以下用平均本身，最少 1 天

按下按鈕會寫入最近一筆更換紀錄，同時更新這一次的到期日，過去的紀錄不變。

把判斷權交還給使用者。有時候拖是因為濾網其實沒那麼快髒 —— 那就按一下調整；有時候是真的懶 —— 那看到這行字自己會有感覺。**自動學習會讓這個訊號消失。**

## 4. 畫面

手機優先。桌面只是把同一套版面加寬，不另做版型。版面細節以原型為準，以下記錄規則。

### 4.1 首頁

**唯一每天會開的畫面。** 職責：一眼看出「現在要不要管」，以及換好了。

- **依位置分組**。位置標題約 20px，前面有位置的 icon
- 位置依設定頁的順序排列，**有逾期物品的位置暫時置頂**，並標示「有逾期」
- **通知關閉時（P3）**，最上方常駐「通知已關閉」與「開啟」按鈕，不可收合。理由：通知關了，app 就不再提醒，跟暫停一樣會靜默失效
- 最上方三個數量方塊：逾期、即將到期、正常。**點擊可快速篩選**：
  - 一次選一個，再點一下取消；被選的加框線、其他變淡
  - 數量維持總數，不隨篩選變動；數量為 0 的方塊不能點
  - 篩選時隱藏沒有符合物品的位置區塊
  - 篩選時「有逾期」標示與置頂，依篩選後顯示的物品判斷（例如篩「即將到期」時不會出現「有逾期」）
  - 篩選中的狀態數量歸零時（例如剛把最後一個逾期的換好），自動取消篩選
  - **離開首頁就清除篩選**（理由見 CLAUDE.md「首頁篩選不要記住」）
- 每一列：
  - 類別 icon（可在設定關閉）
  - 類別（＋補充名稱）
  - 品牌型號 · 週期；沒填品牌型號時只顯示週期
  - 「還有 N 天」或「逾期 N 天」，**不顯示到期日**
  - 「換好了」文字按鈕，垂直置中。逾期與即將到期為實心，正常為淡色
- 最下方**常駐**「N 項已暫停」，篩選時照常顯示，不可收合。理由見 CLAUDE.md「暫停會靜默失效」

### 4.2 物品頁

- **依類別分組**，不使用橫向捲軸；短詞標籤不換行
- 每一列：位置（＋補充名稱）、品牌型號 · 週期、剩餘天數
- **不放「換好了」按鈕**。物品頁用來找東西，首頁用來處理事情
- 暫停中的物品照樣列出，排在同類別的最後

### 4.3 物品詳情

- 剩餘或逾期天數（大數字）、狀態標籤、到期日、上次更換日
- 目前型號（沒填時**整列隱藏**）、目前週期、提前提醒、位置、類別、補充名稱、備註
- 實際間隔回饋（§3.5）
- 物品照片（最多 5 張）
- 更換歷史，每一筆顯示：日期（或「日期未記錄」）、距上一筆天數、品牌型號（沒填時只顯示週期）、型號變更與週期變更標示、備註（有填才顯示）、耗材照片張數、價格。**點一筆可以編輯**
- 動作：換好了、暫停／恢復、編輯、刪除

### 4.4 新增物品

**單頁滾動，不分步驟。**

- 最上方「拍耗材包裝」，自動填入品牌與型號。拍照時手上通常正拿著剛拆封的包裝，拍照比打字自然
  - **分階段**：P1 不顯示；P2 顯示，但只存照片、不自動填入，而且開的是相簿，不是相機；P4 才自動填入品牌型號（照片功能在 P2、辨識在 P4）
- 位置、類別（必填），下方預覽「會顯示為 主臥 · 冷氣濾網」
- 品牌、型號（選填）。白牌、雜牌可以不填
- 補充名稱（選填，預設收合）。同位置同類別已經有物品時**自動展開並提示**
- 上次更換：今天、其他日期、不知道。選「不知道」時改問「下次大概什麼時候要換」，存為第一筆更換紀錄的預計到期日
- 週期（**必填**）：30、60、90、180、365 天或自訂
- 提前提醒：帶入設定的預設值
- 備註（多行）
- 物品照片
- 花費（選填、預設收合）：單價、數量、單位
  - 有填單價就建立採購紀錄；沒填單價但數量或單位動過時提示「請填單價，贈品填 0」。收合時不清空已填的內容
- 新增時同時寫入第一筆更換紀錄

### 4.5 編輯物品

- 可修改：位置、類別、補充名稱、提前提醒天數、備註、物品照片，以及**目前的品牌、型號、週期**
- 後三項存檔時寫入最近一筆更換紀錄，畫面上註明「會寫入最近一次更換紀錄」
- 要改更早的紀錄，從詳情頁的更換歷史點那一筆（§5.4）

*為什麼兩個入口*：補最近一次的直覺上會去按「編輯」；補舊紀錄或改日期只能從更換歷史進去。

### 4.6 設定

- **外觀**：跟隨系統、淺色、深色；**配色**（P2-15）：淺色、深色各 5 組分開挑，預設石板藍灰與深海藍，選了立刻套用，選深色的配色會一併切到深色主題才看得到效果；物品 icon 顯示／隱藏（首頁的類別 icon、物品頁位置名稱前的 icon；標題的 icon 不受影響）。**存在手機本機**，是這支手機的偏好；同時用兩支手機時各自獨立
- **提醒**：
  - 通知（P3）：已開啟／已關閉，只能帶到系統設定開關
  - 提醒時間（P3）：預設 09:00
  - 準時提醒（P3）：系統的「鬧鐘與提醒」權限，沒允許時通知可能延遲
  - 新物品預設提前提醒：只影響之後新增的物品，已建立的不變
- **位置**：列出 icon、名稱、物品數。點一下編輯名稱與 icon；可新增；「調整順序」模式（按住把手拖曳），這個順序就是首頁的排列順序
- **類別**：列出 icon、名稱、物品數。點一下編輯名稱與 icon；可新增
- icon 從**精選清單**挑選，位置與類別各約 30 個。物品不能單獨換 icon，沿用類別的 icon
- **刪除位置或類別**：還有物品屬於它時不能刪除，並提示「還有 N 個物品在這個位置，要先移到別的位置才能刪除」。理由：物品的顯示名稱由位置 ＋ 類別組成，被刪掉的物品會失去名稱
- **資料**：匯出備份、還原（§5.7）。P3 起顯示「上次匯出：N 天前」，超過 30 天或從未匯出時用警示色。理由：資料只存在手機上

## 5. 互動流程

### 5.1 換好了

按「換好了」跳出確認面板：

- 更換日期：今天、其他日期
- 品牌、型號、週期：**全部預填上一次的值**
  - 沒有變動時提示「沿用上次」；上次沒填時提示「上次沒填」；改了之後提示「與上次不同」
- 拍耗材包裝（分階段呈現，同 §4.4）
- 備註（選填，多行）：記這次的情況，例如購買通路。**不預填上一次**
- 這次有買新的（§5.2）

確認後顯示「已記錄 · 復原」。

- **選的日期早於最近一次更換**：照日期插入歷史中間，提示「已記錄 · 日期早於上次更換，到期日沒有變」
- **暫停中的物品**按換好了會自動恢復

*為什麼不是一鍵完成*：原本設計是一鍵直接記今天，理由是「打卡是高頻動作」，那個說法誇大了 —— 全家十幾樣東西、週期一到六個月，一個月只會按幾次。跳出面板讓每次更換都有機會確認品牌型號與週期，沒有變動時兩下完成。

### 5.2 採購

- 在換好了面板勾選「這次有買新的」才建立採購紀錄，展開單價、數量、單位
- 不勾 = 用既有存貨，這次不建立採購紀錄。這正好符合換第 2～5 台冷氣時的實際情況
- 勾了卻沒填單價時提示「請填單價，贈品填 0」，不送出
- 數量預設 1；沒填單位時顯示「個」

### 5.3 暫停

```
[暫停] → 預計什麼時候恢復？（必填）
         [ 3 個月後 ] [ 5 月 1 日 ] [ 指定日期 ]
```

到 `pausedUntil` 自動恢復。首頁常駐顯示暫停項目數。

- 5 月 1 日指下一個 5/1（今天在 5/1 之前是今年，之後是明年）
- 恢復後到期日不順延暫停的天數

### 5.4 編輯更換紀錄

從物品詳情的更換歷史點一筆進入：

- 可修改：日期、品牌、型號、週期、耗材照片（最多 2 張）、備註、價格
- 價格用「這次有買新的」：有採購紀錄時預設勾選並帶入原值；改價格直接改原本那筆；取消勾選時，沒有其他更換紀錄指向的採購紀錄一起刪除；存檔後可復原
- 日期未記錄的那筆可以「補上日期」，補上後清掉預計到期日
- **日期可以改到比其他紀錄早或晚，不跳確認**，但不能晚於今天；存檔後依日期重新排序
- 改日期或刪除導致「最近一次」或到期日改變時，**提示條要寫出結果**並可復原，例如「已儲存 · 這筆現在是最近一次，到期日改為 12/01」
- **只剩一筆時不能刪除**，並說明原因

*為什麼不跳確認*：這類修改很少發生，而且是使用者自己剛做的動作，結果就在眼前。用提示條說明結果並提供復原，比每次多一個確認步驟輕。

### 5.5 刪除物品

- 確認面板列出會一併刪除的更換紀錄筆數與照片張數；有採購價格時一併說明
- 提示「如果只是暫時不用，例如冬天的冷氣，可以改用暫停」
- 刪除後可以復原

### 5.6 照片

- 點加號 → 拍照、從相簿選擇
  - **分階段**：P2 只能從相簿選擇，按加號直接開相簿；P3 改用 Capacitor 相機外掛後加回拍照
  - 理由：網頁版用 `capture` 開相機時，瀏覽器在背景被系統回收，照片送不回網頁（2026-09-14 在 Xperia 5 V 的 Vivaldi 與 Chrome 實測）
- 點照片 → 檢視、刪除
- 物品最多 5 張、更換紀錄最多 2 張，滿了加號就消失
- 上傳前壓縮成 JPEG（見 CLAUDE.md）
- P2 照片選取用 `<input type="file" accept="image/*">`（不帶 `capture`）。帶 `capture` 雖然不需要 HTTPS，但實測拍照後照片會遺失，見上方理由
- 已存檔的物品、更換紀錄：照片加入、刪除都立即生效，不等按儲存；刪除可以復原（先下載原圖，復原時重新上傳）
- 新增物品、換好了：照片先暫存在表單，送出時跟紀錄一起上傳；失敗時什麼都不留下

### 5.7 匯出與還原

- **匯出**：列出內容（物品、更換紀錄、照片、位置與類別的數量）與檔名 `換了沒-備份-YYYY-MM-DD.zip`
- **還原**：分兩步。先警告「會覆蓋目前所有資料」，選擇檔案後顯示備份內容與影響，確認按鈕為紅色
- 備份檔是 zip，內含 `backup.json`（領域資料與格式版本）與照片；不含手機本機的偏好（外觀、物品 icon 顯示）
- 還原是單一交易，失敗時資料不變；按下「覆蓋並還原」前會先自動下載一份目前資料
- 伺服器另外每天自動備份一次，保留 7 份

### 5.8 通知（P3）

- 每天在提醒時間最多一則。當天要提醒的物品合成一則：只有一項時點進該物品，多項時點進首頁，可以展開清單
- 要提醒的物品：進入「即將到期」的第一天、到期當天，逾期後每天提醒直到按「換好了」；暫停中的不提醒
- 通知是預先排好的（外掛不會在背景檢查）：打開 app 與資料變動時重排。排的份快用完時，發「很久沒打開換了沒」提醒打開一次。要預先排多少天，實作時查過 Android 的鬧鐘數量限制再決定
- 新增第一個物品後，先顯示說明面板，再跳系統的權限詢問。理由：Android 的系統詢問被拒絕兩次後就不再出現，而且這時比較看得出通知的用途
- 只做 Android（沒有 iPhone 可以實測）

## 6. 照片辨識（P4）

**定位是「讀出包裝上的品牌與型號」，不是「認出這是什麼東西」。**

比起「這是冷氣濾網」（使用者自己打字更快），真正有價值的是「3M 淨呼吸 9808」—— 那是下次要買同一款時真正需要的字串。

- 輸入：更換紀錄上的耗材包裝照片
- 輸出：建議的品牌與型號
- 使用者可修改後才套用，不直接寫入
- API key 不能放前端。這是**唯一**需要自己寫伺服器程式碼的功能 —— PocketBase 可以用 pb_hooks，或另外起一個小代理
